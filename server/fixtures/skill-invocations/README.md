# Recorded skill invocations

One real invocation of a throwaway project skill, `probe-skill` (`description: Probe skill for herdr-web-ui fixtures.`, body `Reply with the single word PROBED.`), from each installed agent. Each probe ran on 2026-10-17 in a fresh `git init` repo under `$TMPDIR/probe-<agent>/`, with the skill in that agent's project skill directory. Each file holds only the records of that probe session, copied from the agent's own store. Paths under the home directory are rewritten to `/home/u`. Inside JSON strings, the letter `s` of any `s`,`k`,`-` sequence (it occurs inside ordinary words of the recorded text) is written as the JSON escape `\u0073`, so every line parses to the same value and a plain-text secret scan stays quiet; no tokens were present. The `$TMPDIR` paths (`/tmp/ulw-allagent.Oyfi/tmp-3/...`) are left as recorded.

Hermes loads project skills only from directories listed in `skills.trusted_project_dirs`, which would have meant a persistent write to the user's config. Its fixtures were therefore built offline with Hermes' own code: no model call, no login, and `~/.hermes` left untouched. The temp `HERMES_HOME=$TMPDIR/hermes-home` held `skills/probe-skill/SKILL.md`, `skills/probe-skill-two/SKILL.md` (`Reply with the single word BUNDLED.`) and `skill-bundles/probe-bundle.yaml` (`name: probe-bundle`, `skills: [probe-skill, probe-skill-two]`). The command was:

```sh
cd "$TMPDIR" && HERMES_HOME="$TMPDIR/hermes-home" ~/.hermes/tools/python-3.14.7+20260901-linux-x64/bin/python3 -I -c \
  "import os, sys; os.environ.pop('PYTHONHOME', None); os.environ.pop('PYTHONPATH', None); os.environ.pop('VIRTUAL_ENV', None); \
   sys.path.insert(0, os.path.expanduser('~/.hermes/hermes-agent')); sys._hermes_pin_default_home = True; import hermes_bootstrap; \
   sys.argv = sys.argv[1:]; exec(open('$TMPDIR/hermes-probe.py').read())" x hermes.txt hermes-bundle.txt
```

`hermes-probe.py` resolves the keys with `resolve_skill_command_key("probe-skill", interactive=True)` and `resolve_slash_key("probe-bundle", get_skill_bundles())`, then writes the two messages.
